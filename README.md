## 一、项目要解决什么

用户决策入口正从「搜索框」迁移到「对话框」：

| 数据 | 含义 |
|---|---|
| 3.45 亿 | 豆包月活用户 |
| 62.2% | 用户消费决策前优先咨询 AI |
| 96% | 用户不再考虑 AI 未推荐的品牌 |
| 5.1× | AI 搜索转化率相对传统搜索的倍数 |

核心矛盾是：**产品存在，但 AI 不知道它存在。**

豆包采用「信息抓取 → 内容评估（EEAT）→ 语义向量匹配呈现」三阶段机制，抓取优先级为
「7 天内时效 > 权威来源 > 高互动 > 原创 > 结构化」。多平台实体信息不一致会造成信号矛盾，
AI 会降低信任度甚至把品牌排除出候选池。

## 二、解法：GEO 五步法闭环

```
信源布局  →  语义内容  →  多平台分发  →  排名监测  →  迭代优化
 (看见)      (采信)       (记住)        (衡量)       (巩固)
```

| 环节 | 关键动作 | 交付物 |
|---|---|---|
| 信源布局 | 四级信源矩阵 + 实体信息唯一标准 | `01-信源规范手册.md`、`03-账号注册操作手册.md`、`04-账号矩阵登记表.md` |
| 语义内容 | 结论前置 / 分层小标题 / 数据对比表 / 来源标注 / 结尾 FAQ | `content/` 下 19 篇内容资产 |
| 多平台分发 | 官网首发 → 24h 字节生态 → 48h 知识社区 | `05-48h分发执行手册.md`、`06-发布记录表.md` |
| 排名监测 | 52 条问句、三固定原则（账号/设备/时段） | `08-豆包问句测试清单.md`、`09-每周监测与周报模板手册.md` |
| 迭代优化 | 周报驱动，每周 ≥1 条优化动作 | `11-GEO长期运营SOP+月度复盘模板.md` |

## 三、核心设计

### 3.1 四维关键词矩阵（52 条）

不按搜索量堆词，而是按用户在 AI 面前的**真实提问方式**反向拆解：

| 维度 | 数量 | 作用 | 示例 |
|---|---:|---|---|
| 疑问类 | 13 | 拦截需求 | 时间管理工具推荐 / 倒计时 APP 哪个好用 |
| 对比类 | 5 | 拦截竞品 | 闪光倒计时 vs Days Matter 哪个好 |
| 场景类 | 28 | 吃长尾 | 考研倒计时软件推荐无广告 / 项目上线倒计时看板 |
| 避坑类 | 6 | 承接决策疑虑 | 选择倒计时 APP 要注意什么 / 数据丢失怎么办 |

优先级分层：P0 核心词 12 个 · P1 场景词 17 个 · P2 长尾词 23 个。

### 3.2 结构化数据 Schema

落地页嵌入两类 JSON-LD，把产品参数与常见问答显式喂给抓取端：

- `MobileApplication` —— 名称、分类、系统、价格、评分、描述
- `FAQPage` —— 6 条问答，**Question / Answer 必须与页面可见文案逐字一致**（不一致会导致结构化数据被判失效）

### 3.3 工程质量：把规范变成可执行校验

规范只写在文档里一定会在执行中走样。三个 Python 脚本把标准变成硬性检查：

| 脚本 | 校验内容 |
|---|---|
| `validate_c8.py` | 落地页 Schema 字段取值、FAQ 与页面文案逐字一致性 |
| `verify_task10.py` | ASO 元数据字符数、P0/P1 关键词覆盖率、iOS 100 字符上限 |
| `verify_task10_refine.py` | 19 篇内容资产的 5 项 AI 友好格式合规率 |
