01 / Problem

要解决的问题

用户决策入口正在从「搜索框」迁移到「对话框」。品牌在 AI 答案里缺席，意味着在用户心智里出局。

核心矛盾：产品存在，但 AI 不知道它存在。
  • 豆包依托字节 Seed 大模型，采用「信息抓取 → 内容评估（EEAT）→ 语义向量匹配呈现」三阶段机制，抓取优先级为「7 天内时效 > 权威来源 > 高互动 > 原创 > 结构化」；
  • 多平台实体信息不一致会导致信号矛盾，AI 会降低信任度甚至把品牌直接排除出候选池；
  • 纯文本策略效果已下滑，需文本 + 结构化数据 + 多平台信源矩阵并行；
  • 缺少监测手段 → 无法证明优化有效 → 无法迭代，增长动作沦为玄学。

02 / Approach

解法：GEO 五步法闭环

把"被 AI 推荐"这个模糊目标，拆成五个可交付、可验收、可迭代的环节，每一步都有明确产物和量化标准。

看见

信源布局

四级信源矩阵：权威媒体 / 品牌自有 / 垂直社区 / UGC，统一实体信息规范，消除信号矛盾。

采信

语义内容

结论前置、H2/H3 分层、数据对比表、来源标注、结尾 FAQ，全部按 AI 可解析格式生产。

记住

多平台分发

官网首发 → 24h 字节生态 → 48h 知识社区与长尾全覆盖的黄金窗口节奏。

衡量

排名监测

52 条问句、三固定原则（账号/设备/时段），记录推荐与否、排名、引用来源。

巩固

迭代优化

周报驱动，每周至少 1 条优化动作，12 周沉淀为可复制的长期运营 SOP。

矩四维关键词矩阵

不是堆搜索量，而是按用户在 AI 面前的真实提问方式反向拆解：疑问类拦截需求、对比类拦截竞品、场景类吃长尾、避坑类承接决策疑虑。每条标注优先级与意图强度，直接映射到内容形式与首发平台。

构结构化数据 Schema

品牌落地页嵌入 MobileApplication + FAQPage 两类 JSON-LD，把产品参数、评分、6 条常见问答显式喂给抓取端，降低 AI 理解成本、提升引用概率。

验可验收而非凭感觉

把 PRD 里 10 条功能需求拆成 97 项 C-x.y 验收点，并写 Python 脚本对字符数、关键词覆盖、一致性做程序化校验，杜绝"差不多"交付。

04 / Engineering

不只是写方案：把标准变成可执行的校验

内容规范如果只写在文档里，一定会在执行中走样。我用脚本把"AI 友好格式"和"平台字数限制"变成硬性检查。

SCRIPT 01

Schema 与落地页校验

核对 2 类 JSON-LD 的必填字段取值，并逐字校验 6 条 FAQ 的 Question / Answer 与页面可见文案是否完全一致——不一致会让结构化数据直接失效。

SCRIPT 02

ASO 元数据校验

对标题 3 版、副标题 3 版、关键词栏 2 版做字符数统计与 P0/P1 关键词覆盖率计算，同时校验 iOS 关键词栏 100 字符上限、描述前 200 字含核心词等硬约束。

SCRIPT 03

内容合规校验

扫描 19 篇内容资产的结论前置、小标题分层、数据对比表、来源标注、FAQ 模块五项 AI 友好格式要求，输出逐篇合规率。

# 典型校验逻辑：ASO 关键词栏覆盖率与字符上限 def check_keywords(version, text, p0_words): chars = len(text) hits = [w for w in p0_words if w in text] return { "chars": chars, "within_limit": chars <= 100, # iOS 关键词栏硬上限 "p0_coverage": len(hits) / len(p0_words), "missed": [w for w in p0_words if w not in text], }

页零依赖静态落地页

526 行单文件 HTML，内联 CSS 与 Emoji 图标，无外部请求、无构建步骤。首屏 ≤1s 加载，天然满足 AI 抓取端对「结构化 + 快」的偏好，可直接挂 GitHub Pages / Vercel / Netlify。

环监测闭环设计

把"效果好不好"从拍脑袋变成一张表：固定账号 / 设备 / 时段，52 条问句逐条记录推荐与否、TOP 排名、引用来源平台、截图归档，每周出环比周报并反推下轮优化动作。
